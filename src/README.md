# Original C++ implementation

Milestone 2 implements the streaming protocol/registry/settings state in engine.cpp, PTY process lifecycle in main.cpp, locked host-file persistence in storage.cpp, and strict local JSON storage/test envelopes in json.cpp. The local JSON parser is not used to parse Arduino commands. All source is original MIT C++17; no reference headers, routines, classes, or binary EEPROM layouts are incorporated. The [architecture](../engineering/architecture.md), [contract](../CONTRACT.md), and [review](../engineering/development/milestone-2-review.md) define behavior, evidence, and the historical milestone 2 boundary.

Milestone 3 adds original controller evaluation/LCD/scheduling/checkpoint code in controller.cpp and independent filter/thermal/probe dynamics in dynamics.cpp. The physical energy model contains no controller policy. Native main.cpp paces elapsed virtual time while preserving wall-clock serial waits. See the [milestone 3 behavioral mathematics](../engineering/protocol/milestone-3-details.md) and [review](../engineering/development/milestone-3-review.md) for source-informed facts, independent authorship, tests, and evidence limits.

The [cross-milestone review](../engineering/development/cross-milestone-review.md) adds strict local-JSON UTF-8 validation and startup protection for scenario/output aliases. These host-environment checks do not alter Arduino byte parsing, LCD encoding, diagnostics, controller reactions, or EEPROM-like write semantics.

The original optional local display in [lcd.cpp](lcd.cpp) observes a const copy of the existing LCD shadow through engine.hpp. It converts degree cells only at the local UTF-8 presentation boundary, manages a bounded terminal renderer and private Python viewer lifecycle, and never feeds the serial parser or evaluates the controller. main.cpp observes it after ordinary engine work. See the [LCD review](../engineering/development/lcd-review.md) and [operating guide](../docs/operation.md#optional-local-lcd).
