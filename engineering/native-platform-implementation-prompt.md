## Implement and verify in this order

### 1. Protect existing behavior

Inspect [main.cpp](../src/main.cpp), [storage.cpp](../src/storage.cpp), [lcd.cpp](../src/lcd.cpp), current helpers, CMake, and relevant tests. Add meaningful regression coverage before changing their platform boundaries. Keep existing Linux/macOS tests effective; adapt genuinely OS-specific harness operations without silently deleting coverage, converting failures into skips, or changing fixture expectations.

Preserve the exact event-loop semantics established by source: wall-derived physics advancement points, fractional milliseconds, parser deadlines, completed-read/write ordering, partial writes, controller/LCD gating, restart ordering, and disposal of trailing input already discarded by restart. The `65536`-byte pending-output threshold is a backpressure trigger, not a hard capacity or permission to drop bytes. Bounded preposted Windows reads must not feed engine commands through that gate. Retain binary bytes, CRLF, raw `B0`, fixed-point artifacts, diagnostic interleaving, incremental mutations, and one-wall-second parser waits independently of simulation speed. Follow Arduino behavior when questions arise, document findings, and do not repair firmware quirks.

### 2. Implement Windows COM, persistence, and lifecycle operations

Use original Win32 operations for exclusive existing COM handles, cancellable waits, and bounded asynchronous I/O. Support explicit canonical `COMn` names, including numbers above `COM9`. Use the owner-authorized operator-provisioned pair record and check both recorded names against their approved HHD virtual-device identities before opening the selected endpoint. Detect reassignment and reject physical, missing, or busy endpoints without fallback or scanning/opening arbitrary ports. Treat the peer association as operator-provisioned information, not automatic discovery or proof of current provider wiring. Require a replacement record after reprovisioning, disclose that limit, and do not add a provider SDK or undocumented hooks.

For example, the emulator selects `--serial COM8`, while its external client's configuration uses `port = COM7` and `altport = None` on the opposite end. These are illustrative, not authorized device selections. Preserve `57600`/8N1, actual client control-line behavior, startup with an unopened peer, explicit purge semantics, finite-buffer behavior, slow readers, and close/reopen. Distinguish intentional client purges from unexplained provider byte loss. Do not invent resets, messages, or commands on open/close.

Keep engine mutations on the shared loop. Track outstanding operations and partial completions until completion/cancellation releases ownership safely. Preserve cooperative console interruption, abrupt-termination recovery, and existing checkpoint eligibility. Account for outstanding application writes before applying the drained-output guard. OS-buffer acceptance does not prove peer consumption; retain the documented operator drain/stop procedure without an unbounded flush barrier.

Provide private ownership/publication information and nonconsuming readiness without opening either occupied COM end or treating a PID as authentication. Do not derive a relative `COM7.lock` path. Keep runtime operation unprivileged after approved external provisioning.

Implement equivalent Windows store locking, bounded regular-file reads, path-identity checks, same-directory replacement, and flushing/failure semantics. Exercise Unicode/spaced paths, aliases, hard links, reparse points, busy/read-only files, and collisions. Preserve pre-replacement failure and uncertain post-replacement durability; do not promise a whole-command transaction or universal power-loss guarantee. Use explicit writable `--state` paths without migration or writes beside the installed executable.

### 3. Preserve existing controls and macOS PTYs

Carry forward headless mode, Python-free terminal controls, and the optional Python/Tk LCD/control helper. Optional means optional for the user, not omitted from full-feature platform acceptance. Preserve `cw`, `ccw`, `press`, door controls, menu confirmation/expiry, dimming, fallback, GUI-close intent, and exclusion of drafts from checkpoints. `Enter` submits terminal text; it does not replace `press`. A reduced-feature delivery requires a separate scope decision.

Adapt only Windows terminal/process/IPC mechanisms needed for the existing bounded, versioned action protocol. Choose the smallest demonstrated mechanism; do not preselect a new protocol or network service. Restrict handle inheritance, keep IPC private to the user, avoid shell execution, and reject stale/duplicate actions. Port the helper's transport rather than assuming Windows accepts POSIX descriptors.

On macOS, retain the raw PTY, stable symlink, and existing controls unless a reproduced defect justifies a scoped change. Use the same explicit absolute `--serial` path in host `port`, set `altport = None`, and provide writable `--state`. Do not add default-path policy, shell-variable/`~` expansion, or automatic virtual-port discovery. Preserve Linux defaults. Verify reopen after process replacement.

Run pinned native pySerial checks, including `flushInput()`, `flushOutput()`, and `flush()`. Investigate the documented macOS PTY drain-hang risk on the actual matrix; a reported upstream issue is not proof of an emulator defect. Do not patch the external host, fake successful drain behavior, or silently substitute a transport. Review any required dependency change before accepting the matrix.
