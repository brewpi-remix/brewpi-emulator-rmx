# Command semantics

These original MIT notes describe parser, device, storage, and numeric behavior alongside the [wire contract](behavioral-contract.md).

The custom scalar/time/flag reader accepts an integer prefix consisting of digits and minus signs; the presence of a minus sign makes that prefix negative. It requires a digit, rejects a leading plus and exponent suffix, and permits a decimal point as the end of an integer prefix. A scalar's first fractional prefix is separately parsed; its fixed-point fraction is rounded at each decimal reduction, rather than rounding a binary floating-point value once. A second decimal point can terminate that fractional prefix without rejecting the remaining text. Scalar sign handling also examines minus signs anywhere in the token. Flags and times validate their integer prefix before narrowing/clipping, so arbitrary text is not accepted as zero. The filter/query/device integer paths use their documented `atol`/`atoi`-style prefix behavior instead. Source facts: [numeric conversion](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/TemperatureFormats.cpp#L143) and [custom integer grammar](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/TemperatureFormats.cpp#L349).

F input is quantized to fixed point before temperature conversion. Absolute conversion subtracts 32 F before multiplying by 5/9 with signed nearest rounding, then applies the -48 C internal offset; difference conversion omits the absolute offsets. Conversion order is observable at rounding boundaries. This is a mathematical specification, not a translated converter. Source facts: [unit conversion](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/TemperatureFormats.cpp#L251).

Reload forces the saved mode action, even if its character did not change. Saved off-mode targets are therefore disabled and the resulting settings are stored during reload. An ordinary `j` `mode:o` while already off can leave subsequently written targets intact until that reboot. Waiting-for-peak state 7, as well as waiting states 5/6, forces an ordinary mode action. Source facts: [forced reload and mode action](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/TempControl.cpp#L628).

Ordinary `U` patch members first become signed-byte values and apply only when nonnegative; calibration instead treats only -1 as omitted. Applied pin/function/hardware fields enter unsigned-byte storage. A supplied ROM beginning with `FF` is treated as omitted. Raw noncanonical boolean representations, malformed ROM conversion, and reference-dependent arithmetic remain fidelity gaps needing characterization; do not create native undefined behavior or invent Arduino diagnostics for them. Source facts: [device storage types](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.h#L169) and [patch application](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L417).

Diagnostic string arguments must retain the firmware's unescaped content, even when a literal backslash makes the `D` payload invalid as strict JSON. The test envelope and host-file store use a separate strict local JSON codec; they do not impose their escaping rules on serial records. Source facts: [wire logger](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/Logger.cpp#L42).

## Follow-up review corrections

Ordinary `U` patch fields `i/c/b/f/h/p/x/d` are signed-byte selectors, and only nonnegative values are applied to stored fields. Every negative value is omitted on application, not merely -1. A later negative duplicate replaces an earlier pending value, so it can cancel that pending field's update. Calibration is different: any signed byte except -1 applies, including other negative offsets. `FORCE_DEVICE_DEFAULTS` still determines ownership from the supplied signed `f` value, so a negative `f` patch on an existing beer record can yield `E7`/`E3` instead of preserving its beer owner. The follow-up review corrected the earlier unsigned-function claim and its erroneous regression expectation; `f:-2` on an empty slot leaves function 0 and returns a cleared `U` record. Source fact: [conditional patch assignment](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L384).

Discovery has separate mutable cursors for each OneWire bus and digital enumeration. Assignment leakage within each cursor remains required, but probe fields must not leak into the first digital pin row. Digital `h` results omit `v` even with `v:1`; temperature `h/d` values have three decimal places, while ordinary `T` values have two. In `d`, a nonnegative `w` suppresses `r` only for switch actuators: sensor records can still be read with `w` and `r:1` together. Numeric device attributes pass through signed-byte output, so a stored pin 200 prints -56. Sources: [discovery boundaries and values](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L741), [d read/write behavior](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L930), and [attribute output](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L545).

A configured ROM whose first byte is `00` wildcard-matches inventory regardless of its remaining bytes; its live read still uses the literal configured address. Even-length short ROM inputs overwrite only their supplied bytes in the pending patch's initially `FF`-filled address. Repeated addresses retain bytes from the earlier pending value beyond the new prefix. `FF`-family pending addresses remain omitted on installation. The reference's bounded lowercase conversion is also nonstandard: letter values are derived relative to uppercase `A` before nibble combination, so a low-nibble lowercase letter can change the high nibble (`1a` becomes `3A`). Odd-length or excessive addresses remain characterization-required; do not pad them into an invented valid record. Sources: [address parsing](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L628), [wildcard matching](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L678), and [pending definition initialization](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L395).

The implementation stores only the latest pending recognized field for `h/d/U`, retaining the reference's fixed-field state rather than accumulating an unbounded list of duplicates. This is not a command-length limit or transaction rejection: arbitrary-length sequences still apply their final recognized fields, `j` remains incremental, and invalid calibration conversions retain the preceding valid pending calibration. Unknown fields consume no pending state.

Numeric scalar/difference/absolute saturation uses raw -32766 through 32767, reserving -32768/-32767 for invalid/disabled temperatures. Only explicit `null` input selects the disabled sentinel. For example, `Kp:-64` saturates to raw -32766 and reads -63.996; an excessively low absolute setting saturates to a finite minimum rather than becoming `null`. This corrects the implementation's earlier plain `int16` lower bound. Unit conversion can itself overflow the reference's 32-bit arithmetic for extreme tokens; those paths remain characterization-required rather than silently using a wider host result. Sources: [reserved values](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/TemperatureFormats.h#L70) and [saturation](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/TemperatureFormats.cpp#L316).

Raw `NUL` bytes inside tokens count toward the 29-character token capacity, but callback strings are visible only up to their first `NUL`. For example, a `Kp` token followed by `NUL` and junk still names `Kp`, and value 7 followed by `NUL` and junk still supplies 7. The implementation keeps capacity accounting separate from callback-string visibility. This is a bounded communication fact, not escape decoding or a new rejection rule. Source fact: [token termination and callback invocation](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/PiLink.cpp#L705).

Ordinary configuration validation precedes installation and resulting-record output. A candidate that fails function/owner/hardware validation emits that failure and `E3` followed by old `U`, even if an unused pending boolean byte is noncanonical. The native fidelity-gap guard must not preempt such a defined validation failure; it applies only before actually observing/installing a valid candidate with a noncanonical boolean representation. Source fact: [validation before installation](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DeviceManager.cpp#L449).
