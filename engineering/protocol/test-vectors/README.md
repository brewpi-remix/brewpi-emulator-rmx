# Original protocol fixtures v1

These are original MIT specification fixtures for milestone 1, not captured firmware transcripts, a test runner, emulator code, a runtime configuration schema, or passing conformance evidence. They were authored from the [behavioral contract](../behavioral-contract.md), [defaults](../defaults.md), [diagnostics](../diagnostics.md), and [firmware findings](../firmware-findings.md). The referenced firmware/host/panel revisions are recorded in each JSON artifact. Copyright 2026 Lee Bussy; SPDX-License-Identifier: MIT. JSON metadata and this adjacent notice cover formats without comments.

## Artifacts and scope

| File | Contents |
| --- | --- |
| [defaults-v1.json](defaults-v1.json) | Exact reference identity, fixed-point-derived C/F defaults, cold V, original synthetic ROMs, inventory, explicit initial-state presets, controller timing, and independent external plant inputs. |
| [diagnostics-v1.json](diagnostics-v1.json) | All 43 type/ID metadata signatures and representative typed arguments, classified by reachability; no upstream diagnostic prose or source enums. |
| [protocol-v1.json](protocol-v1.json) | 57 independently authored cases: 48 source-defined wire/semantic cases and nine explicitly unqualified characterization cases. |

Metadata samples are examples of argument shapes, not evidence that a path was executed. Source-defined means the expected response is derived from the cited source/profile and explicit fixture preconditions; it does not mean verified on Arduino or emulator. A characterization case has no invented exact reply and counts_as_pass=false. All artifacts state execution_status=not_executed_against_emulator_or_reference.

## Data format and matching rules

Each artifact has schema_version=1, a format identifier, SPDX/copyright/authorship metadata, and pinned revisions. This is a documented fixture format, not a JSON Schema implementation. A future runner must reject unknown format versions and validate these structural rules before claiming execution. Each protocol case has a unique id, classification, initial_preset, finding IDs, and steps or a required characterization stimulus. Presets are references into defaults-v1.json; each case starts independently. Do not carry mutations between cases.

Resolve a preset's extends chain from parent to child, overriding only supplied fields. settings/constants/variables/slots strings refer to the named root datasets; controller_preconditions refers to the explicit default-controller-precondition object. Empty slots means all 16 records are zeroed in a valid store, whereas not_initialized means the erased/invalid-version fetch path returns no slot records. In an initialized preset, live and saved settings/constants/slot records initially agree unless a field explicitly distinguishes them. Seed raw_defaults and variables_raw_cold directly; rounded readback values are expectations, not a recipe for reparsing the store. The profile_saved_20 preset overrides both live and saved settings and the last-saved-target marker. Assigned presets seed the declared filter histories and physical readings, not only the response JSON.

set_fixture_precondition is a field patch of the declared reference state; omitted values retain their current values, and variables_raw patches named raw fields rather than replacing the complete V state. mode, beer_target_c, fridge_target_c, slow_beer_c, fast_fridge_temperature_c, beer_slope_c_per_hour, diff_integral_raw, cool_estimator_raw, and integral_evaluation_count refer to the corresponding live reference quantities, not serial writes or callbacks. controller_seconds/controller_millis must describe the same clock; seconds_since_idle is a derived timestamp constraint whose timestamp/history must be constructed coherently, including reference-width wrap when applicable. required_probe_connected describes the required live sensor connection. Camera state requires both an explicit active flag and last-active timestamp. There is no implicit command, annotation, time advance, or persistence from constructing a precondition.

persisted_device_records replaces only the saved slot set, filling unlisted slots with zeroed records while retaining a valid EEPROM version/settings/constants; it does not install live targets or normalize c/b. A later R/reload performs validation and installation. This permits source-defined boot-validation fixtures without adding a serial storage-edit API or a copied EEPROM implementation. Other state/history setup is declarative test construction and must be reported separately from raw-interface execution.

serial_write supplies exact chunks_hex; input_display is explanatory only. Decode hex to input bytes in the given chunk order, without appending a newline or JSON reserialization. All fixture pauses suppress autonomous loop ticks unless a step explicitly requests one; command callbacks still have their normal synchronous effects. allow_serial_read_timeout permits the selected firmware's approximately one-second no-data read window to expire, rather than advancing the simulation clock or introducing a new parser API.

A serial R step covers issuance of the no-acknowledgment command, not completion of boot. await_controller_restart is a lifecycle barrier before subsequent input: finish reconstruction/reload and collect that phase's specified boot diagnostics, then restore the fixture's controlled tick boundary. It sends no implicit serial bytes and supplies no fake firmware response. Move reset-dependent postconditions to that barrier. controller_boot similarly represents completion of a declared initial boot phase. A future hardware run must qualify its real boot-readiness observation/timing; an arbitrary delay or an immediate next query is not proof that R completed. These controlled phases are specification test conditions, not a claim that physical firmware can be paused through its serial interface.

An expected reply contains prefix and exactly one of payload_equals, payload_contains, or payload_ref. A ref is a same-directory artifact name followed by a JSON Pointer into that artifact. Resolve it before comparison. Equals requires the exact decoded JSON value, including absence versus null, numeric/string/bool types, and array order. Integer/decimal spellings represent the same JSON number, but bool is not an integer. Contains on an object requires the specified key/value projection; contains on a list requires an ordered subsequence of objects matching each projection. It does not waive separately listed findings or permit invented defaults in unmentioned fields.

expected.diagnostics lists exact required type/ID/V records for the observation window. output_order, when present, orders reply prefixes and D:typeID labels; repeated labels refer to the next unused matching entry. When absent, diagnostic order follows the behavioral contract and the listed per-kind sequences; fixtures that depend on interleaving use explicit order. additional_output=none_before_next_explicit_tick prohibits extra forced acknowledgments, extra T frames, or debug-guarded messages in that window. If the source's physical call can log inside a list, use a raw stream characterization/byte expectation rather than force an atomic-frame interpretation.

The controlled window ends only after the declared input has been consumed and its callbacks finish, a specified read timeout expires, or a lifecycle barrier completes; silence alone does not prove consumption or reboot completion. Runtime runners must report their observation mechanism/deadline and distinguish harness timeout from a controller result. Suppressed autonomous ticks make these conditional source-state fixtures reproducible; later ordinary-clock integration must separately include legitimate asynchronous output. No extra-byte tolerance or passing timeout is implied.

raw_hex takes precedence over decoded payload matching and must match exact output bytes, including CRLF, padding, field order in that vector, and non-UTF-8 LCD byte B0. It is not an invitation to normalize all streams to strict UTF-8 JSON. The explicit raw identity/settings and LCD cases have finite observation windows and declared initial state. Other cases use semantic payload matching without claiming bit-identical source whitespace in every numerical trajectory.

set_fixture_precondition and controller_* steps are declarative semantic test conditions, not proposed serial commands, a new management API, or an implemented harness. Future tests may construct the declared sensor/controller history or use test-only observation, then exercise the same production behavior. repeat counts evaluations, not necessarily simulated seconds; this matters for the integral-counter bug. effective filter coefficients and camera latches are semantic observations whose externally visible consequences also need later integration evidence. Do not present source-state setup as physical Arduino execution.

requires_reference_trace cases define stimulus and required_evidence, with expected_exact_output=null and counts_as_pass=false. A future runner must report them as unresolved/characterization-required, never passing or silently skipped success. They remain fidelity obligations. Retain the exact reference artifact/initial state/timing when later qualified; do not replace unknown outcomes with safe new validation behavior.

## Coverage and provenance

The cases cover startup and exact identity/default replies; split/coalesced bytes; invalid tab/brace/unknown setting; repeated/partial/trailing-comma and overlong-key/stale-value objects; empty-object queries; C/F conversion and raw precision; byte-narrowed inputs; slot/query selectors; discovery aliases; assignment/ownership/duplicate behavior; saved-record reload validation; calibration's -1 sentinel; deactivation/removal and room omission; reused enumeration state; actuator/camera/alarm handling; S/C/E/R persistence differences; profile save thresholds; optional disabled commands; LCD export; live beer-filter routing; camera test-mode timeout; derivative/integral/minimum-on behavior; stale V and narrowed integral readback; and literal zero-ROM behavior. Characterization vectors explicitly track unsafe slot/ROM/uninitialized-record cases, complex duplicate/latch histories, drift arithmetic, sensor-transaction timing/embedded diagnostics, extreme conversion overflow, and pin/OneWire conflicts.

The three ROMs were chosen for this project and their CRC bytes computed with independent one-off data arithmetic. Default numbers were independently calculated from the documented raw fixed-point facts; no reference module was imported or executed. The fixtures were not generated from emulator output or a copied implementation. The [milestone provenance record](../../licenses/milestone-1.md) records authorship, dependency disposition, and the artifact validation actually performed. No claim of runtime conformance or approval to implement follows from this fixture set.
