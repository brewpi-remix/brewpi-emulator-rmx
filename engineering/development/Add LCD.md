Preserve the firmware's layout, wording, display history, temperature precision, room alternation, and timers. The lowercase o substitution from the research example is withdrawn.

## Existing behavior and source evidence

The emulator already stores an LCD shadow in [controller.cpp](../../src/controller.cpp), serializes it for command l in [engine.cpp](../../src/engine.cpp), and retains its history in checkpoints. The screen accessor is currently private; [main.cpp](../../src/main.cpp) has no local display switch. Reuse that shadow instead of deriving a second screen from telemetry, calling command l internally, or forcing extra controller evaluations.

The reference is the selected ordinary Uno/RevC firmware at 8f1fa1213cbbfc1f987fada5168d01925e1a2ee8. Its [LCD layout](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/DisplayLcd.cpp), [normal loop](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/Brewpi.cpp#L102), and [UI update](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/UI.cpp) establish the following presentation facts:

- The first row contains Mode at column 0 and its value at column 7; the next two rows contain measured and target temperatures beginning at columns 6 and 12. Column numbers are zero-based.
- The Beer row stays visible. The next row alternates Room and Fridge in eight-controller-second phases when ambient is connected; Room suppresses the fridge setpoint. Without ambient, retain the Fridge view.
- Rows 1 and 2 end with the degree cell at column 18 and the selected C/F unit at column 19. Invalid or disabled temperatures use the existing --.- presentation.
- The last row contains the existing state phrase and, where applicable, a right-aligned elapsed or remaining timer. Door status overrides the displayed state without replacing the underlying control state.
- Ordinary updates occur on controller evaluations approximately once per controller second, with existing blocking, pause, acceleration, reset, and stationary-repaint behavior preserved. A local redraw must not refresh stale cells ahead of the engine.

The physical LCD degree character is 0xDF. [Firmware serial export](https://github.com/brewpi-remix/brewpi-firmware-rmx/blob/8f1fa1213cbbfc1f987fada5168d01925e1a2ee8/src/SpiLcd.cpp#L238) substitutes raw byte 0xB0; the emulator already retains the exported representation. Map that degree cell to Unicode U+00B0 only at the local presentation boundary. Do not change serial L payloads to UTF-8, reinterpret the entire payload as UTF-8, or change the host's CP437 handling. Finding F16's unresolved low-level reference timing/history qualification remains open.

## Proposed command-line contract

| Invocation | Proposed behavior |
| --- | --- |
| No display option, or --lcd off | Existing headless execution; no viewer process, terminal control, or Python runtime requirement. |
| --lcd terminal | Show the Unicode LCD in the terminal; Python is unnecessary. |
| --lcd gui | Attempt the Python graphical LCD and fall back to the Unicode terminal on startup failure or later viewer termination. |
| --lcd auto | Select the graphical LCD when it can actually initialize, otherwise use the Unicode terminal. This is an explicit opt-in, not the default. |

Accept only the documented values and reject an invalid value as a CLI error before runtime outputs are created. Missing Python/Tk, missing helper, unavailable graphical session, GUI initialization timeout, IPC failure, and later child exit are viewer availability failures: report the reason once, try terminal fallback, and continue the emulator. Do not treat a genuine emulator/storage/PTY error as a reason to hide the error behind display fallback.

Both gui and auto guarantee an attempted terminal fallback; they do not guarantee that a terminal exists. Open the controlling terminal separately from the serial PTY. If there is no accessible controlling terminal, disable local display with one diagnostic and continue headless. Never emit cursor controls into redirected stdout/stderr or invent an ASCII degree substitution. Document that correct terminal rendering requires a UTF-8-capable terminal and a font containing °; a viewer cannot guarantee the appearance of an incorrectly configured terminal.

The runtime transition order is GUI_STARTING → GUI_ACTIVE → TERMINAL_ACTIVE → HEADLESS, allowing startup failures to skip GUI_ACTIVE. A suspended terminal panel remains TERMINAL_ACTIVE and can resume on resize or foreground recovery. off enters HEADLESS immediately, terminal skips the GUI states, and gui/auto have identical failure semantics; auto expresses preference rather than a strict GUI requirement. Headless is terminal for display selection during that process. There is no retry loop, duplicate panel, or automatic switch back to GUI. Viewer-only failure must not alter the emulator exit status; preserve existing nonzero exits for actual application errors.

These are proposed switches, not runnable commands in the current application. Update --help and operator examples only during an authorized implementation task.

## Shared presentation and runtime design

1. Add a const, side-effect-free engine accessor returning a copy of the four retained byte rows. Do not expose mutable screen storage, generate serial output, poll the PTY, or call render_display from the accessor. Keep current checkpoints and controller persistence unchanged.
2. Add an independently authored local presentation adapter that produces exactly four rows of twenty display cells. Accept printable ASCII bytes unchanged, map byte 0xB0 to U+00B0, and map every other byte to the single ASCII replacement cell ?. Do not use a whole-string Latin-1, CP437, or UTF-8 decode. This explicit supported repertoire prevents escape sequences, combining marks, and wide characters from corrupting local cell geometry. Preserve spaces and positions; report unexpected bytes once outside the LCD and keep the original shadow/serial data unchanged. Reject a malformed local frame with the wrong row count or row length as a viewer error; do not repair engine data. Measure columns by cells, not UTF-8 byte counts.
3. Observe the latest shadow after normal engine work. Refresh on changes with a maximum of ten presentation updates per wall-clock second, plus an initial frame after boot/resume and explicit redraws after terminal resize. Use wall-clock scheduling only to bound rendering cost; room phases, state timers, and source screen updates remain on controller time. Intermediate presentation frames may be coalesced at high acceleration; controller evaluations and protocol output may not be dropped or rescheduled for the viewer.
4. Keep terminal writes and GUI publication nonblocking with bounded storage. On a slow consumer, retain the latest complete screen and finish any partially transmitted terminal frame before sending another. Never interleave partial frame fragments or let a stuck viewer stall serial processing, shutdown, or checkpoint creation. Bound each serialized viewer message to 4096 bytes, each encoded terminal frame to 4096 bytes, and userspace display output to one in-flight frame and one latest pending frame per destination. Limit viewer reads/writes to eight messages and 32 KiB per event-loop turn; resume remaining work on a later turn. Treat five wall seconds without output progress as viewer failure. These are presentation budgets, not firmware timeouts. Kernel socket buffering is finite and must be recorded during testing; do not grow it dynamically to hide a stalled consumer.
5. Keep viewer mode, child state, IPC queues, and redraw deadlines outside engine checkpoints and EEPROM-like storage. Capture the saved LCD shadow before advancing a resumed engine and offer it as the initial frame; never delay the engine waiting for a viewer to paint it. If GUI initialization takes longer than that frame's lifetime, coalescing may make the first visible GUI frame newer. Terminal initialization can offer the saved frame immediately. Default startup and controller R retain their current semantics.

## Unicode terminal presentation

Use a fixed, bordered panel containing the existing twenty cells per row. The degree glyph occupies one cell despite being two bytes in UTF-8. Illustrative values below are original examples, not physical LCD captures or test evidence:

```text
+--------------------+
|Mode   Beer Const.  |
|Beer   20.0  20.0 °C|
|Fridge 19.5  19.0 °C|
|Cooling for    03m12|
+--------------------+
```

Open /dev/tty independently using O_WRONLY, O_NOCTTY, O_NONBLOCK, and close-on-exec; never change nonblocking flags on inherited stdout/stderr or on the serial PTY. Verify that it is a terminal, that the emulator is in its foreground process group, and that the locale reports UTF-8 with a one-cell width for U+00B0. If those checks fail, report the specific limitation and continue headless rather than emit mojibake or an ASCII degree substitute. Do not call setlocale globally to change controller numeric formatting; use a scoped locale object or equivalent isolated capability check. Do not read terminal input, request cursor-position reports, install raw input mode, or compete with the shell for keystrokes.

Use a conservative supported ANSI/VT capability set for in-place redraw, selected without a new runtime library; unknown or dumb terminal types use the append-only presentation. Reserve six lines and repaint relative to that region using carriage return, cursor-up, and erase-line operations. Do not hide the cursor, use the alternate screen, change scrolling margins, or change termios. Route application diagnostics that share this terminal through the same bounded output scheduler: finish an in-flight frame, retire its region, print the diagnostic, and redraw beneath it. Preserve diagnostic text and redirected log destinations. New viewer diagnostics must not add blocking writes to an existing stdout/stderr pipe. Existing fatal error reporting retains its application semantics; local display cleanup is best effort. Output from unrelated processes can still disturb a shared terminal, so the next completed repaint restores the panel without claiming exclusive terminal ownership.

Perform resize and foreground checks at redraw boundaries, including a periodic check while paused. A resize during an in-flight write invalidates its cursor geometry: discard the remaining presentation bytes, separate the next output with a newline, and allocate a fresh region once the terminal is usable. An already active terminal viewer temporarily suppresses writes in a background process group and resumes in the foreground; an initially unavailable background terminal follows the startup headless rule. Guard the foreground-check/write race with a scoped thread-local SIGTTOU mask around terminal operations and treat EIO/background outcomes as suspended rendering; restore the mask afterward and do not change global signal dispositions or controller scheduling. No terminal state needs restoring beyond retiring the region on clean exit. SIGKILL cannot guarantee retirement or complete UTF-8 output and is not a clean-shutdown test.

For a terminal without the supported cursor-addressing capabilities, append complete changed Unicode snapshots at most once per wall-clock second, with a wall-clock timestamp outside the LCD border. For a terminal smaller than 23 columns by 7 rows, suspend either presentation and report the required size once; resume when the terminal fits. The LCD border itself is 22 columns by 6 rows; the additional column and row avoid right-margin autowrap and bottom-edge scroll hazards. If dimensions cannot be established, disable display with an explanation. Do not wrap, truncate, or shift LCD cells to fit. Bound partial writes for either presentation as described above; on an unrecoverable write error, stop local rendering rather than repeatedly write to a broken terminal.

## Optional Python graphical LCD

Use Python 3.9 or later with tkinter and the Python standard library. Tkinter provides a suitable cross-platform GUI interface but is optional and requires a working graphical session; see the [official Python documentation](https://docs.python.org/3/library/tkinter.html). Do not infer availability from DISPLAY alone: graphical initialization and an explicit readiness response determine success. No Qt, Pillow, downloaded font, image asset, or pip dependency is proposed.

Run the viewer as a separate child so the C++ control loop remains independent of Tk's event loop. Draw an original green-background LCD panel with eighty fixed character cells, readable dark text, the proper degree glyph, and scalable spacing. Preserve the exact row layout and text. A dot-matrix font or hardware-accurate pixel/contrast/backlight simulation is outside the first implementation; no firmware font or asset may be reused. Resizing changes cell scale, not row/column count. Display no controller-editing controls.

Use a private inherited Unix-domain datagram socket pair for complete bounded local UTF-8 JSON messages. Frames contain schema/version, a monotonically increasing sequence, and four twenty-cell rows from the shared adapter. Reject unsupported versions, oversized/truncated datagrams, invalid UTF-8/JSON, incorrect types, and characters outside the supported repertoire. Detect datagram truncation using a maximum-plus-one receive buffer or equivalent flags. Use nonblocking parent sends, coalesce to the latest pending frame on backpressure, and have the viewer consume a bounded batch and paint only its newest complete frame. Datagram boundaries avoid partial JSON-frame corruption. The viewer sends only bounded ready/error/progress messages; no incoming message can mutate the engine or issue a serial command. Malformed or excessive child messages cause viewer failure and fallback rather than unbounded parsing or logs. Close unrelated inherited descriptors, especially the serial PTY and storage locks. No listening network port, filesystem socket name, host socket, or additional serial client is needed.

Launch the interpreter/helper using posix_spawn-style explicit argument vectors and descriptor actions without a shell. Resolve the helper using the configured installed libexec location or the explicitly configured build-tree path; never search the caller's working directory for a same-named helper. Select python3 using the normal executable search path and report the actual selection for diagnostics; use isolated Python mode so helper behavior does not depend on user site packages or Python environment imports. Execute no automatic installer. Give the child null stdin/stdout/stderr and use only the structured private channel for errors, avoiding inherited log-pipe backpressure and stray tracebacks on the panel. Pass only the required channel descriptor in addition to those standard descriptors. Account for transient spawn descriptors without clobbering the PTY or lock descriptors.

The child imports tkinter, creates and maps its window, initializes a system font, and signals ready through the Tk event loop after its first paint. Draw each cell separately so font fallback cannot shift subsequent columns. Tk readiness and text-width measurement alone do not prove that a font displayed ° instead of a missing-glyph box: require a real visual check of °C and °F for each advertised desktop environment, and document font coverage as an environment requirement. A detectable font/window initialization error triggers fallback; do not promise automatic detection of every missing-glyph rendering defect. Set a five-wall-second startup deadline monitored by the existing event loop; continue normal emulation throughout. Before readiness, retain only the latest frame. Startup failure starts terminal fallback immediately and begins child cleanup concurrently; do not wait for reaping before fallback or block the control loop in waitpid. If the installed helper or interpreter cannot be resolved, skip spawning and record the reason once.

Keep all Tk operations on the GUI thread and use short scheduled callbacks to consume the nonblocking socket. Both sides send one heartbeat per wall-clock second, with the viewer's progress heartbeat produced only by its Tk event loop. Five seconds without viewer progress causes terminal fallback even if the GUI process remains alive. If the viewer receives no parent heartbeat for ten seconds, it exits; a paused controller still sends heartbeats because presentation uses wall time. A process-wide suspension longer than this lease may close the GUI and cause fallback on resume, with no engine reset. Datagram sockets have no stream EOF guarantee, so socket closure alone is not a parent-loss detector.

Closing the graphical window ends the viewer, activates terminal fallback, and leaves the emulator running. Do not automatically relaunch a closed or failed viewer. Detect/reap child exits with nonblocking waitpid restricted to the owned PID, without overriding SIGCHLD behavior for unrelated children. After viewer failure, request termination and allow two wall seconds before killing that owned child if needed; perform cleanup through event-loop deadlines while emulation continues. On application shutdown, run the existing clean-checkpoint decision first with no new engine advancement, then close the viewer channel, terminate/reap its owned child with the same bounded grace period, and retire the terminal region best effort. Do not make checkpoint success depend on display queues being drained. Preserve the original application error/exit status when cleanup also fails.

The interpreter and Tcl/Tk are external optional runtime dependencies. A desktop may run the viewer while the emulator is headless elsewhere only in a later explicitly scoped transport design; remote GUI transport, container display passthrough, and Windows-native emulator support are not added here.

## Adversarial review and dispositions

The following findings were identified in self-review of the earlier draft and resolved in this revision. These are design dispositions with required future tests, not claims of executed feature tests or proof that all future implementation defects are impossible.

| Finding | Revision and required acceptance evidence |
| --- | --- |
| A01: Reconstructing telemetry or requesting l would create a second display policy or compete with the host. | Observe a const copy of the retained shadow only. Compare raw serial bytes, engine snapshots, and saved state for identical deterministic histories with each display mode. |
| A02: Replacing the serial degree byte with UTF-8 would break Arduino/host behavior; arbitrary byte decoding could inject terminal controls. | Convert only at the local adapter using the explicit ASCII-plus-degree repertoire and single-cell ?. Test all 256 input bytes, exact row geometry, unchanged B0 serial export, and both units. |
| A03: A copied descriptor shares file-status flags; modifying stdout nonblocking could affect callers. | Independently open /dev/tty, leave inherited stream flags unchanged, and keep viewer diagnostics bounded. Test redirected streams, serial traffic, and descriptor flags before/after fallback. |
| A04: A 22-by-6 terminal can wrap or scroll at the final border cell; resize can invalidate a partially written frame. | Require 23 by 7, retire/reallocate the region on resize, and use a single output scheduler for application diagnostics. Test exact size boundaries, resize mid-frame, partial UTF-8 writes, logging, and paused resize recovery. |
| A05: TERM, DISPLAY, and an import succeeding do not prove a usable console or graphical window; font metrics cannot prove glyph appearance. | Check foreground/UTF-8/cell width/dimensions for console; require a mapped and painted Tk window plus readiness. Test missing session, non-UTF-8 locale, unknown TERM, small terminal, and missing Tk. Visually verify both degree/unit combinations; do not advertise universal missing-glyph detection. |
| A06: Setting the global locale could change controller number formatting. | Keep locale capability checks scoped; retain invariant controller formatting. Test non-C numeric locales and unchanged serial decimals. |
| A07: Bounded frames alone do not prevent queued history, message floods, or CPU monopolization. | Apply explicit message/queue/per-turn budgets, coalesce frames, validate truncation, and expire stalled consumers. Test oversize/type/version errors, flooding, slow readers, and bounded memory/serial latency at 1x/10x/60x. |
| A08: A live GUI process can hang after readiness; datagram closure is not EOF. | Use Tk-loop progress and parent heartbeats with distinct leases and a one-way fallback state machine. Test hung Tk loop, quiet paused engine, parent SIGKILL, suspend/resume, and no repeated GUI restarts. |
| A09: Waiting for child death before fallback can hang the emulator; inherited PTY/locks can prevent cleanup. | Start terminal fallback before asynchronous owned-child cleanup; pass only the intended descriptor and null standard streams. Test ignored SIGTERM, forced termination, PID ownership, orphan cleanup, lock release, and no FD growth over repeated runs. |
| A10: Requiring the resumed frame to be visibly painted before time advances would couple simulation to GUI startup. | Capture and offer the saved shadow without waiting; document first-visible-frame coalescing. | A11: Closing the window or lacking any terminal could leave fallback behavior undefined. | Window close continues the emulator in terminal mode; missing/unusable terminal continues headless with one explanation. | A12: GUI cleanup or pending display bytes could block checkpoints or mask an application error. | Make checkpoints independent of viewer queues, perform their existing decision first, and preserve the primary exit status. ## Owner revision: deliberate close stops emulation

The owner subsequently requested running the local GUI and explicitly required closing that GUI to stop the emulator. This supersedes earlier deliberate-window-close fallback behavior in this plan. The helper sends a bounded close lifecycle message and exits with reserved local status 10 as a race/backpressure fallback. The emulator recognizes either signal as normal shutdown intent, applying its existing checkpoint preconditions and cleanup. Unexpected viewer crashes, startup failures, and liveness failures still select terminal/headless fallback. This is local application lifecycle policy, not an Arduino command or controller change.
