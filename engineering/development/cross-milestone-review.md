## Coverage and findings

The review covers the source-backed protocol/default/diagnostic/fixture contract, original parser/registry/persistence code, controller/filter/timer/thermal/checkpoint implementation, host/panel launcher and evidence handling, target qualification/install/readiness tooling, and operating/provenance guidance. Historical milestone records retain their original evidence; this record describes later corrections. The reviewed firmware remains authoritative, including bugs. The nine characterization obligations are still unresolved and are never counted as passes.

| Area | Finding and correction |
| --- | --- |
| Host lifecycle and read-only scenario input | A process could read a scenario and later replace that same file with its checkpoint. Reproduced against the prior executable with a zero exit. Startup now rejects scenario aliases of runtime output/lock paths before locks or PTY publication, using normalized paths and existing-file identity. Original process regressions cover direct, normalized, hardlink, and symlink checkpoint collisions and byte preservation. This host-path policy adds no firmware command or diagnostic. |
| Strict local JSON versus firmware byte protocol | The local JSON reader accepted invalid raw UTF-8, including an overlong encoding, despite rejecting invalid escaped Unicode. Reproduced against the prior driver. Validate multibyte scalars, shortest encoding, continuation bytes, Unicode range, and surrogate exclusion in local JSON strings. Original regressions accept valid multibyte text and reject malformed encodings. Arduino token grammar, raw LCD B0, diagnostic escaping quirks, and reviewed wire expectations are unchanged. |
| Integration versus qualification evidence gates | The integration launcher still ignored cleanup failures and could report success with absent/nonpassing child evidence; it executed a mutable image tag. It now uses the original shared evidence finalizer, requires 17 passing workflows, browser/application cleanup, reference/source integrity, and native fixture reports, verifies owned-container removal, protects finalization from repeated signals, and executes the inspected immutable image ID. Explicit prebuilt-image reuse avoids changing the environment during an offline review; rebuilding remains the default. |
| Original inputs versus external-client integrity | Milestone 4 audited external clones but not changes to original inputs through the host side of its read-only mount. Both isolated workflows now use one original source-input inventory helper, with before/after hashes and separate reports. External client capture/assets still remain ignored and retain their own provenance. |
| Repeatable specification validation | Earlier metadata/link/pinned-path checks depended on an original temporary helper outside the repository. The original checker is now saved under tests/specification.py with MIT notices and repository-relative root discovery. It requires the prepared sibling references, reads pinned objects with git show, and never executes or imports reference code. |
| Operating and status consistency | Clarify private scenario/output separation and filesystem errors after rename: pre-replacement failure preserves old bytes, but a reported directory-sync failure after replacement cannot guarantee the old checkpoint remains. Remove obsolete milestone-5-unapproved text from the integration guide, record all five published baselines, and retain the current no-commit/no-push boundary. |

Source inspection found no additional established deterministic Arduino discrepancy in the reviewed parser/device/controller/filter/default/diagnostic paths. This is a bounded review, not proof of full AVR equivalence. Existing missed-read accumulation, lowercase-ROM conversion, live-versus-saved resets, incorrect beer-filter routing, camera/test behavior, integral cadence, timing boundaries, and narrowed telemetry remain intentional.
