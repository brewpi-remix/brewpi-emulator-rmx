## Implemented decisions

The [approved plan](rotary-controls-plan.md) and [operator guide](../../docs/operation.md#local-rotary-and-door-controls) define local control exceptions. The original source-informed [firmware findings](../protocol/firmware-findings.md) remain historical reference facts; serial command parsing, acceptance, replies, persistence, and unrelated controller quirks are unchanged. The owner's later deliberate GUI close/Quit requirement supersedes the plan's older blanket continue-on-close sentence: deliberate closure stops normally, while actual GUI failure falls back.

The C++ engine owns a staged menu, explicit local confirmation, physical door input, and a transient LCD overlay. Mode/target drafts do not alter saved settings or live controller state; exact unrotated targets survive confirmation, while rotated targets use the display-unit tenths grid inside exact bounds. Invalid/disabled and out-of-range initial targets use bounded selections; reversed bounds refuse editing, and intervals without a tenth preserve exact confirmation with no-increment feedback. Range reconciliation remains local and explicit: external bounds changes cancel drafts and never silently clamp serial targets. Constant-mode confirmation applies mode then target in firmware setter order with existing saves, evaluation, and deferred output writes. This grouping does not promise crash-atomic storage.

Graphical controls include a center-press rotary knob, labeled step/press alternatives, focused keyboard access, and an authoritative Open door/Close door button. A terminal owns a separate nonblocking controlling-terminal description and a single rewritten command/status line. Accepted commands are cw, ccw, press, door open, door close, and help. Acknowledgments last 750 wall milliseconds; input/acknowledgment/prompt do not scroll per command. Overlong/invalid lines are rejected through their terminator. Basic editing, CR/LF deduplication, resize, foreground ownership, Ctrl-C, and pre-job-control mode restoration are covered. Unsupported terminal types remain explicitly read-only; interactive layout needs 23 columns by 8 rows.

Both presentations dim text after strictly more than 60 wall seconds; --lcd-keep-on disables dimming. Input wakes and acts normally; the first press opens the menu. Menu inactivity uses ten wall seconds and 384 ms blink phases. Background controller and plant operation continues under existing pacing, serial blocking, and backpressure semantics. A local conflict revision observes intermediate serial mutations and excludes routine PID-derived fridge updates from beer drafts. Resets, ownership/viewer loss, and checkpoint resume discard drafts. The local overlay is visible to l while active but excluded from the retained base-shadow checkpoint; S/T and saved settings contain no previews. Plant door state retains its existing physical/checkpoint ownership and device-assignment/inversion semantics.

Private IPC version 2 retains lifecycle/frame bounds and adds session/action IDs, conflict revisions, acknowledgments, and door/dim metadata. The GUI allows one outstanding action without blind retries; stale revisions reject with feedback, and duplicate/malformed input cancels/falls back. Deliberate closure still uses its close message/reserved exit race protection. Local engine/storage failures propagate as application failures rather than being swallowed as viewer failures. No network listener or second serial client is introduced.
