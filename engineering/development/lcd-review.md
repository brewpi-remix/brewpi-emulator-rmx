## Result and interfaces

--lcd terminal displays the existing four-by-twenty shadow with proper Unicode degree cells. --lcd gui and --lcd auto prefer the optional Python graphical LCD and automatically select the terminal on startup/liveness/window/IPC failure; no usable terminal means headless execution. An omitted option and --lcd off keep headless operation without opening a viewer or requiring Python. The read-only engine accessor returns a copy; the adapter changes only the local presentation, retaining raw B0 serial export, controller schedules/state, persistence, firmware quirks, and checkpoint schemas. See the [operating guide](../../docs/operation.md#optional-local-lcd).

The original code uses C++17/POSIX and an optional standard-library Python/Tkinter helper. A private inherited datagram channel carries bounded frames/lifecycle messages; no viewer opens serial, a host socket, or a listening network port. GUI startup, heartbeat and output-stall timeouts are wall-clock presentation policy, separate from controller time. The console retains terminal input modes and inherited stream flags, suspends for small/background terminals, and bounds/coalesces output. Old Tk 8.5 is rejected following an actual blank-canvas observation; Python 3.9+/Tk 8.6+ is the supported GUI prerequisite.

## Design refinements made during implementation

- CMake copies the original development helper beside the build executable and discovers the installed helper relative to the configured bindir/libexec relationship. No absolute source/build path is embedded for development discovery; the caller's working directory is never searched for a helper. This avoids the initial prototype's build-root-dependent binary strings.
- The default fresh install remains six original project files. The explicitly selected lcd-viewer component adds one original helper, giving seven; Python/Tcl/Tk/fonts/captures are excluded. Existing R4 manifests, saved packages, hashes, and version metadata are unchanged. Future feature-bearing candidate packaging needs its own complete allowlist/inventory and new identity; this task does not run a new freeze.
- Optional diagnostics are best effort under backpressure. Linux reopens stderr with a separate nonblocking description; macOS does not mutate an inherited blocking pipe. An unsafe/full sink can suppress a viewer diagnostic rather than stop emulation. Existing application startup/fatal diagnostics preserve their destinations and failure semantics.
- Userspace holds the current shadow, one in-flight terminal frame, and the latest pending state rather than a history. Messages and terminal frames are at most 4096 bytes. The parent permits at most six incoming messages plus two outgoing messages per turn, no more than 32 KiB. The GUI permits seven incoming messages and one progress send per callback. The requested parent SO_SNDBUF is 8192 bytes; Linux reports 16384 bytes in the installed-helper check; platform-returned values are reported through the bounded viewer diagnostics. No buffer grows in response to a stalled viewer.
- GUI initialization may coalesce away an older initial/resume presentation frame while emulation proceeds. Engine checkpoints remain exact and do not depend on a window painting a frame. Ordinary GUI window closure continues emulation with terminal fallback, without automatic relaunch.

## Review boundary

No known finding remains after the repeated code/design, execution, and final receipt/build assessments. All named final execution receipts were inspected and passed. ## Owner follow-up: local GUI and stop on close

The owner subsequently requested a local native GUI demonstration and required deliberate GUI closure to stop the emulator. This supersedes the earlier close-to-terminal policy for deliberate closure only. The original helper now sends a close lifecycle message and returns reserved local status 10; either requests normal emulator shutdown. Queued close intent is consumed before reaping a child, and status 10 covers a lost/backpressured close message or exit race. Unexpected child exits and actual GUI failures still fall back automatically. Controller and serial semantics are unchanged, including existing checkpoint preconditions.

The native demonstration used Homebrew CPython 3.14.10 with Tcl/Tk 9.1, supplied by the official python-tk@3.14 package, plus its libtommath 1.3.0 and tcl-tk 9.1.0 dependencies. These are external host runtimes, not bundled or MIT-relicensed project bytes. This follow-up installed those optional host dependencies to make the GUI available; the preceding implementation review installed no host toolkit. The helper binds both the close button and macOS Quit to deliberate shutdown.

The user viewed and closed the private native instance under runs/lcd-live-g039y1z_. Its emulator exited with status 0, removed its serial symlink, and saved checkpoint.json. The updated regressions cover explicit close intent and the reserved-exit race separately from crash fallback. Earlier immutable review source snapshots and validation receipts remain historical records of the preceding revision, not identities for this follow-up. No commit, push, release, service activation, or physical controller operation was performed.
