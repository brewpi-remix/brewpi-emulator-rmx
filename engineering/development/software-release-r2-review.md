## Findings and corrections

| Finding | Correction and regression coverage |
| --- | --- |
| Every job output carried the entire source inventory. Eight base64 receipts, identity fields, and native/floor reports could exceed the Linux per-environment-string process limit when passed together through RMX_NEEDS; source growth worsened that risk. | Record the canonical source-inventory SHA256 in the identity, compare it across the completion gate, keep the full map in local evidence, and bound each emitted receipt to 8,192 bytes. Eight outputs plus needs metadata remain bounded. Test a real child process receiving all eight receipts, reject oversized outputs, and reject mismatched fingerprints. |
| Native Linux guests created root-owned bind-mounted reports that a normal hosted runner could not finalize. | Run native and floor guests with the runner UID/GID and a guest-local writable home; test Docker arguments and actual unprivileged native execution/host report finalization. No host Docker socket is mounted. |
| Linux emitted its receipt before container cleanup and minimum-tool execution. A failed wrapper could leave a passing-looking primary report, even though its failed job result prevented overall acceptance. | Defer guest output, emit exactly once from the host wrapper after both containers and required floor checks complete, extend the completion timestamp through cleanup, and archive/invalidate a provisional receipt on wrapper failure, retaining a structured failed receipt even for image-build failure. Mocked wrapper regressions verify no output before cleanup, no host output-file mount in the guest, and failed cleanup rejection. |
| UBSan normally recovers from some findings, allowing a native test that reports undefined behavior to exit zero. | Add -fno-sanitize-recover=all to the existing optional sanitizer configuration. The normal Release build and Arduino semantics are unchanged. Run the native sanitizer suites and an original overflow canary with actual CMake target flags; the canary must exit nonzero. This follows the [compiler's recovery-mode documentation](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html). |
| Completion proofs did not reject a native receipt for the other architecture or nonfinite execution timestamps. | Require the declared native machine/system for the lane, the exact source fingerprint, finite positive ordered timestamps, and complete named suite proofs. Negative subtests cover wrong architectures, NaN/infinity, stale inputs, failed/nonexecuted dependencies, and omitted proofs. |
| Integration/qualification finalizers required fixture counts but did not require evidence that all six named native suites actually ran. | Run CTest in dashboard test mode, parse its six named passed Test.xml entries using the shared original native helper, save execution.json with each native result set, and require those reports alongside unchanged 48/9 fixture counts. Missing, incomplete, wrong-name, or nonexecuted XML/report cases fail. |
| Payload receipts were compared with one another, allowing a self-consistent but unrelated identity/hash set to satisfy that part of the finalizer. Installed source-file integrity and source executable restart reports were not required. | Bind saved records to the independently supplied frozen manifest/commit and exact manifest-byte SHA256, require the expected ordered phases and selected executable path, validate installed-file integrity against the initial full inventory, and require all source/package restart/completion hashes. Missing reports, wrong identity/version/architecture/files, or missing phases fail. |
| A consistently rehashed payload could replace the project's MIT license. | Require the extracted project license bytes to match the reviewed root MIT license, independently of its manifest hash; reject changed terms and a boolean schema masquerading as integer 1. This does not replace the later final-artifact provenance/notice audit. |
| Host/panel CI checked the host machine but not the selected tool-image architecture. | Require the actual selected image to report ARM64 before starting the required host/panel lane; reject a wrong-architecture image in a negative test. |
| Integration log collection still expected LastTest.log after dashboard mode was introduced. | Collect exactly one legacy or timestamped CTest log; reject absent or ambiguous logs. The initial failed review attempts were retained with verified cleanup before the corrected runs. |
| Qualification's comment inferred an isolated guest from Debian 12, while direct root execution could reach prefix-reset code on a host. | Before provisioning, require the launcher's explicit disposable-qualification marker and an actual /qualification tmpfs mount. Only the existing allowlisted guest test prefixes may be reset. Negative tests reject absent/wrong markers and ordinary host filesystem layouts. The host prefix is never mounted. |

The workflow still owns the same nine exact PR/main check names with contents-read permissions, pinned actions, 60-minute limits, no path-based skips, and no scheduled/release/deploy workflow. The always() completion job still rejects failed, skipped, neutral, cancelled, missing, mismatched, and incomplete receipts. Required contexts remain proposals until a separately authorized publication and hosted run; repository rules are not activated here. Receipts are unsigned execution evidence, not attestations or protection against an unreviewed contributor rewriting workflow code.
