# Milestone 5 qualification scope

The owner selected the isolated Debian 12 ARM64 Linux environment for milestone 5. The target is a Linux ARM64 container on the available Docker/LinuxKit host, not a physical Raspberry Pi or an AVR reference artifact. Qualification covers native Release/Debug/sanitizer builds, original fixture regression, unprivileged PTY ownership and nonconsuming readiness, firmware-style blocking waits, slow-reader backpressure, process/reboot/checkpoint distinctions, measured pacing, staged install contents and dynamic-library closure, and operator guidance. No commit, push, live deployment, or physical-device action is authorized.

New operational helpers and tests are independently authored MIT work. Readiness must verify the live process and raw accessible character endpoint without reading, consuming startup diagnostics, sending serial commands, altering the port, or changing controller state. The optional systemd example uses the normal foreground process and an ExecStartPost readiness gate; unit syntax is checked with the target's systemd-analyze, and its actual command/readiness lifecycle is exercised as an unprivileged account. The container does not boot systemd as PID 1, so these checks do not establish actual system-manager activation or boot ordering.

CMake install staging must contain only the original executable, original readiness helper/service example, original license/notices, and selected original operating/provenance documents. Do not bundle reference clients, screenshots/captures, test dependencies, source-generated reference tables, or operating-system libraries. Inspect the staged manifest and actual ELF dependencies; no package or release is published.

Controller millis/seconds, timer thresholds, parser behavior, identity, and documented bugs stay unchanged. Wall-time metrics are evidence for the selected machine/workload, not a universal response SLA or firmware conversion-time oracle. The nine reviewed characterization obligations remain unresolved without the exact reference firmware artifact and physical/bus/history evidence; do not call them passing or claim affected parity. No Arduino or Fuscus implementation is imported or executed as an emulator dependency.
