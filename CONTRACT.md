# Project contract

BrewPi Emulator Remix is an independently authored C++17/Linux replacement for the selected Arduino controller personality. It provides a serial PTY and a virtual fermentation chamber for the BrewPi Remix host and web panel. See the [operating guide](docs/operation.md) and [protocol reference](engineering/protocol/README.md).

The selected Arduino firmware's observable action/reaction governs serial and controller behavior, including deterministic bugs. Record uncertain behavior; do not replace it with stricter parsing, atomic updates, corrected filters, different defaults, or new replies. Undefined-memory and hardware-dependent cases remain compatibility limits without invented passing outcomes. Local controls stage drafts and validate confirmation independently of serial acceptance.

Original source, tests, helpers, fixtures, configurations, and prose use the [MIT License](LICENSE.md). Preserve contributor notices and source/helper SPDX identifiers. Do not copy, vendor, link, translate, adapt, or mechanically rewrite BrewPi/Fuscus implementation, headers, routines, tables, tests, or assets, including through AI-assisted transformations. Required interoperability values and source-backed behavioral facts belong in original specifications. Standard equations and conventional algorithms may be implemented independently. This is source-informed development, not a claim of formal clean-room separation.

Reference applications run separately as external compatibility clients. Their licenses remain their own. External compiler/runtime contributions and redistributed source keep their applicable notices and terms; original emulator work remains MIT. Apply the [provenance review gate](engineering/licenses/README.md#review-gate) and keep the [component inventory](THIRD_PARTY_NOTICES.md) accurate. Source inspection and native tests do not establish physical Arduino/Pi qualification, service activation, or power-loss durability.

Keep operator guidance in `docs/`, current technical reference in `engineering/`, original implementation in `src/`, development tests in `tests/`, and build/package utilities in `cmake/` and `release/`. Do not add planning histories, phase reports, raw captures, machine-local state, credentials, or downloaded reference code to distributions. Public/accepted releases are retained unchanged. Commits, pushes, tags, releases, deployment, and physical-device work require the owner's instruction.
